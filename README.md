# 繁花·纷落角色卡档案：AI 上传规范

这是本仓库的维护说明。任何 AI 在新增角色卡、替换图片、修改角色数据或重新部署之前，都必须先阅读本文件。

仓库中的两个文件职责固定：

```text
index.html  网站本体，不要用另一套页面重写它。
README.md   本文件，给后续 AI 的角色卡上传、构图和验证规则。
```

## 1. 最重要的图片规则：眼睛和头部优先

角色卡原始 PNG 可以保留完整立绘，但网页预览必须优先显示人物的头部和眼睛。

每一张卡都必须满足：

- 预览框内能看到眼睛，或者至少能看到完整的眼睛所在面部区域。
- 头顶、眉毛和眼睛不能被预览框上边缘裁掉。
- 不允许出现“只看到胸口、身体、手部或下半张脸，看不到眼睛”的预览。
- 脸部应位于预览区域上半部，眼睛线建议落在预览高度的 15%–35% 范围内。
- 可以保留肩膀和上半身，但头部优先级高于胸口、服装、手部和背景。
- 不要为了展示全身而把人物头部缩得过小。

当前页面的默认展示焦点是：

```text
previewPosition: "50% 8%"
```

其中：

- 第一个百分比是水平位置，`50%` 表示水平居中。
- 第二个百分比是垂直位置，数值越小，画面越向上，越优先显示头部。
- `8%` 是当前页面默认的“眼睛/头部优先”位置。

如果某张卡的人脸仍然偏低，可以使用：

```text
previewPosition: "50% 4%"
```

如果某张卡的头顶已经贴近上边缘，才允许稍微向下调整：

```text
previewPosition: "50% 12%"
```

一般禁止使用：

```text
previewPosition: "50% 50%"
```

因为这会恢复容易裁掉眼睛的居中裁切效果。

## 2. 新角色卡数据格式

新增作品时，在源站作品数据中加入 `previewPosition` 字段。示例：

```js
{
  name: "角色名称",
  image: "assets/cards/example.png",
  preview: "assets/cards/example.png",
  previewPosition: "50% 8%",
  alias: "角色别名",
  cardLabel: "角色身份"
}
```

字段要求：

- `name`：角色名称。
- `image`：原始 PNG 的相对路径，必须真实存在。
- `preview`：网页预览地址；没有单独预览图时可以和 `image` 相同。
- `previewPosition`：两个百分比，中间用空格分隔，例如 `50% 8%`。
- `alias`、`cardLabel`：有真实资料时填写，不要编造。

如果旧数据没有 `previewPosition`，当前 `index.html` 会自动使用默认值 `50% 8%`，不会回到 `center` 居中裁切。

只有当单张图片构图明显特殊时，才针对单张卡填写 `50% 4%` 或 `50% 12%`。不要为了单张卡复制一套 CSS，也不要重写页面 DOM。

## 3. 原始 PNG 和网页预览不是同一件事

必须严格区分：

1. 网页预览：使用 `object-fit: cover` 和 `previewPosition`，目的是让眼睛和头部出现在展示区域。
2. 原始 PNG 下载：必须从源站、jsDelivr 或 GitHub Raw 获取完整 PNG，不能下载网页截图，也不能用 Canvas 重新生成假 PNG。

因此，网页上看到的可以是“头部优先裁切”，但点击“保存角色卡 PNG”得到的必须仍是完整原始文件。

## 4. 给 AI 的机械执行步骤

新增角色卡时，严格按以下顺序操作：

1. 先阅读本 `README.md`。
2. 检查当前 `index.html`，不要根据聊天记录重写页面。
3. 将完整原始 PNG 放入源站的角色卡资源目录。
4. 确认路径、文件名和大小写完全正确。
5. 在作品数据中加入 `image`、`preview` 和 `previewPosition`。
6. 默认使用 `previewPosition: "50% 8%"`。
7. 打开卡片列表，确认第一眼能看到眼睛或头部。
8. 打开详情弹窗，确认顶部图片仍能看到眼睛或头部。
9. 打开保存面板，确认预览不会只显示胸口。
10. 下载 PNG，确认下载的是完整原始 PNG，文件大小不为零。
11. 检查浏览器控制台没有 404、`image-error` 或未处理 Promise rejection。
12. 确认作者数量、首张卡、末张卡和已有卡片都没有被破坏。
13. 完成本地测试后，再提交 GitHub 并等待 Pages 部署成功。

## 5. 禁止事项

- 禁止把所有卡片的默认位置改回 `object-position: center`。
- 禁止只调整截图，不在作品数据或页面规则中记录焦点位置。
- 禁止用 Canvas 生成假的角色卡 PNG。
- 禁止为了新增卡片修改原始 `.archive-card` DOM 层级。
- 禁止重新设计标题栏、卡片 chrome、详情弹窗、保存面板或原始动画。
- 禁止删除源站、jsDelivr 和 GitHub Raw 备用图片来源。
- 禁止上传聊天附件、本地基准文件或 `original-index.html`。
- 禁止把上传规范写进一段无法被后续 AI 找到的临时聊天内容；本 README 才是规范来源。

## 6. 最终验收标准

新增卡片只有在以下条件全部满足时才算完成：

- 列表卡片能看到眼睛或头部。
- 详情弹窗顶部能看到眼睛或头部。
- 保存面板预览不会只显示胸口。
- 原始 PNG 下载有效，文件大小不为零。
- 源站失败时，预览仍按 jsDelivr、GitHub Raw 顺序尝试备用来源。
- 桌面、平板和手机宽度下没有横向溢出。
- 页面没有新增桌面/手机设备模式按钮。
- 页面没有出现第二套卡片 CSS 或另一套 modal 结构。
